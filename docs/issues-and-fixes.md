|---|---|---|---|---|
| 1 | 2026-11-21 | Hopsworks login failed with `UnicodeEncodeError` | Invisible zero-width space copied with the API key | Strip non-alphanumeric characters from the key; verify length (81) |
| 2 | 2026-11-21 | Forecast API returned future hours of the current day | API serves model forecasts for the rest of today | Filter `ts <= current hour` during ingestion (issue #6) |
| 3 | 2026-11-21 | AQICN nearest-station lookup returned Ahmedabad (~600 km away) for Karachi | No live AQICN station near Karachi | Distance guard (50 km) |
| 4 | 2026-11-21 | Only AQICN station in Karachi (US Consulate) reports no AQI, last update March 2025 | Station decommissioned | Reject non-numeric and stale (>3 h) readings; AQI comes from Open-Meteo/CAMS (modelled), listed as a limitation |
| 5 | 2026-11-22 | First imputation draft interpolated the first 3 h of a long outage linearly | pandas `limit=3` fills the first 3 NaNs of every run, even inside a longer gap | Compute the length of each NaN run and only interpolate runs of at most 3 h; longer gaps use the value of the same hour on the previous day |
| 6 | 2026-11-22 | `test_store` passed alone but failed in the full test run | `config` reads env variables at import time, so a test that sets them later is too late; a model saved by an earlier run polluted the default folder | `tests/conftest.py` gives every test an isolated temp store and registry |
| 7 | 2026-11-23 | Secondary-source rows (e.g. OpenWeather without wind direction) turned numeric columns into text | `None` values make pandas infer an object column; the feature store rejects mixed types | Convert all raw columns with `pd.to_numeric` and normalise dtypes (`_store_ready`) before writing |
| 8 | 2026-11-23 | A long backfill range in one request risks API limits | Open-Meteo limits request size | Fetch in 31-day chunks |
| 9 | 2026-11-23 | Backfill joins ERA5 reanalysis (old dates) and model analysis (last 88 days) | The archive API has no recent data | Documented as a limitation; a small level shift is possible at the join |
| 10 | 2026-11-24 | First write to the feature store failed: "delta library is not installed" | Hopsworks creates DELTA feature groups by default and its Python client needs the `deltalake` package | Added `deltalake` to the pipeline and dashboard requirements |
| 11 | 2026-11-24 | Insert failed on Windows with hdfs-native / Kerberos warnings and "RPC listener disconnected" | A non-stream DELTA feature group makes the client write directly into HopsFS, which is not reachable from a local machine | Created the feature groups with `stream=True`: rows go through Kafka and a Hopsworks job materialises them. Feature group version bumped because the mode cannot change on an existing group |
| 12 | 2026-11-24 | Warning: casting timestamp 'ts' from ns to us loses precision | Hopsworks stores microsecond timestamps | Normalise timestamps to `datetime64[us]` before writing |
| 13 | 2026-11-24 | Backfill insert rejected: "humidity / wind_dir expected bigint, got double" | Open-Meteo returns whole numbers for humidity and wind direction; in a 30-day sample with no gaps pandas kept them as int64, so the feature group was created with bigint columns. A longer range contained gaps, so the same columns became float | Cast all raw columns to float64 before writing; regression test added; feature group version bumped to 3 because a schema cannot be changed |
| 14 | 2026-11-24 | Backfill insert failed with Kafka "Broker transport failure" after the first group had succeeded | Transient connection problem between the client and the Hopsworks Kafka broker | Inserts are retried up to 3 times with growing waits (safe because they are upserts on the primary key); tests added |
| 15 | 2026-11-26 | A backfill silently wrote to the local fallback store instead of Hopsworks | The API key was not set in that terminal session, and the store falls back to local files without a warning | `ingest` now prints which backend it writes to; always check for `writing to HopsworksBackend` |
